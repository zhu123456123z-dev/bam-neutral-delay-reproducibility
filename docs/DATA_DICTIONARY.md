# Data dictionary

The output grid has 2001 points from 0 through 40, spaced by 0.02. Physical state order is `x1, x2, y1, y2`. The remaining four components in the augmented system are memory variables. The parameter file defines the three initial histories and all coefficients.

## MATLAB archive

`04_results/matlab_derivative/simulation.mat` contains:

| Variable | Shape | Meaning |
| --- | --- | --- |
| `p` | MATLAB structure | Model and numerical parameters |
| `t` | 1 x 2001 | Output times |
| `zr` | 8 x 2001 | Augmented reference solution |
| `trajectories` | 4 x 2001 x 3 | Physical state trajectories for three histories |
| `errors` | 3 x 2001 | Maximum absolute physical state error relative to the reference |
| `reference_derivatives` | 4 x 2001 | Reference state derivatives from the right-hand side |
| `trajectory_derivatives` | 4 x 2001 x 3 | State derivatives for the three histories |
| `derivative_errors` | 3 x 2001 | Maximum absolute derivative error |
| `joint_errors` | 3 x 2001 | Elementwise maximum of state and derivative errors |
| `validation` | MATLAB structure | Refinement, history-horizon and solver metadata |

`trajectories.csv` has **no header**: columns are `t, x1_ref, x2_ref, y1_ref, y2_ref, state_error1, state_error2, state_error3`. It is not the full set of individual-history trajectories; those are in the MAT file.

`derivative_errors.csv` has **no header**: columns are `t, dx1_ref, dx2_ref, dy1_ref, dy2_ref, derivative_error1, derivative_error2, derivative_error3`.

`condition_matlab.json` contains matrix criterion values and positive-vector certificates for eta=1 and eta=2. `matlab_validation.json` contains the actual MATLAB version and empirical numerical checks.

Each figure basename has PNG, PDF and FIG versions. The PNG exports are 300 dpi; PDFs contain vector graphics; FIG files remain editable in MATLAB. Paper figures 1, 2, 3, 4, 5 map to export names `fig1_states`, `fig2_histories`, `fig3_errors`, `fig5_derivative_errors`, `fig4_regions`, respectively.

## Python archive

`04_results/python/simulation_python.npz` is loadable with `numpy.load(..., allow_pickle=False)`:

| Variable | Shape |
| --- | --- |
| `t` | (2001,) |
| `zr` | (8, 2001) |
| `trajectories` | (3, 4, 2001) |
| `errors` | (3, 2001) |
| `reference_derivatives` | (4, 2001) |
| `trajectory_derivatives` | (3, 4, 2001) |
| `derivative_errors`, `joint_errors` | (3, 2001) |

The meanings match the MATLAB variables, but the history dimension comes first. Both Python CSV exports have header rows and the same column meanings as their MATLAB counterparts. `python_validation.json` is the original saved solver record, not a record of the packaging machine.

## Intermediate calculations

Fine-tolerance and longer-history responses were compared during simulation, with scalar maxima saved in validation records; their full interpolants were not archived. They can be regenerated by rerunning the relevant solver. Do not describe this release as preserving every internal solver step or all intermediate responses.
